# 已知问题

## KI-001 仿真“斜面上旋转的英雄”无法稳定重建

- 记录日期：2026-11-15
- 状态：**已解决**（2026-11-20 移植武科图像平面 UVL + `DiffMeasure` 观测后关闭，`uvl_tracker_test` 斜面旋转回归 `180/180` 零失锁、`med|w_err|=0.05 rad/s`、`med_px_err=0.53 px`）
- 影响模块：`tasks/auto_aim/target.*`、`tasks/auto_aim/tracker.*`、`src/sim_standard.cpp` / 网页 viewer

### 现象

仿真的英雄在斜面上旋转时，网页右侧 3D 重建的四块装甲板不是连续旋转，而是每隔约 0.4 s 跳一次/重置；左侧原图的检测框仍然能跟住当前那块板。

### 复现与证据

```bash
build/sim/sim_pose_probe configs/sim.yaml -frames=120 -target=one
```

探针输出（节选）：

- `det_yaw` 在约 −1.05 rad 和 +0.17 rad 之间换板，`jumped=1`，`last_id` 在 0/1/3 之间切换；
- `w` 估到约 −4.6～+2.5 rad/s，说明视觉**确实看到了旋转**，不是把目标当静止；
- `r` 在约 0.11～0.26 m 之间振荡，`l` 在 −0.08～+0.12 m，`h` 在 −0.06～+0.02 m；
- 每约 12 帧出现：
  ```
  [Target] r=0.049, l=0.144
  [Tracker] Target diverged!
  ```
  随后 `no target`，跟踪器重新初始化，`armor_xyza_list()` 的相位被清零。

### 根因

当前 `Target` 的 11 维状态假设：

- 装甲环在**水平面**内；
- 只有两个半径 `r`、`r + l`（id 1/3 用 `r + l`）；
- 只有两个高度 `z`、`z + h`（id 1/3 用 `z + h`）。

仿真英雄的四块装甲根半径并不在同一个圆上（`HERO.glb` 约 0.21 / 0.26 / 0.28 / 0.21 m），而且它位于斜面上，装甲环平面本身就是倾斜的。换板时 `r/l/h` 被来回拉，`r` 会掉到 0.049，触发 `Target::diverged()` 的 `r > 0.05` 检查，跟踪器重置。

注意：四块板半径/高度不完全相同本身**不是仿真 bug**，制作规范允许一定偏移（见下节）；是当前 EKF 把它们强行压成“两个半径、两个高度”才不稳。

### 硬约束（用户明确）

- **不允许**预先知道/硬编码某台机器人四块板各自的半径 `r_i`、高度 `z_i`（由底盘设计决定），以及斜面导致的装甲环平面倾角；
- **不允许**读取共享内存里的 GroundTruth 来补偿视觉；
- 必须从单目观测中在线估计（sim2real），不能针对仿真英雄硬编码 0.21/0.26/0.28。

### 可以使用的制作规范先验

敌方装甲板一定符合 RM 制作规范，规范是**合法先验/约束**，不是“已知答案”。来源：

`/home/scj/桌面/rm2027/rule/UTF-8__RoboMaster 2027 机甲大师高校系列赛机器人制作规范手册V1.0.0（20261015）.pdf`

- §3.6.1.1 S120（P61）：4 块装甲模块的方向向量分别对应机体 ±X、±Y（相邻板 90°）；受击面法向量与 −Z 的锐角为 **75°**（板面相对竖直约 15°）；不含侧灯的两条边与 XY 平面夹角 <5°。
- §3.6.1.1 S121（P61）：X 轴上装甲几何中心连线与 Y 轴上连线互相垂直；单块板在垂直方向的偏移量 ≤ **50 mm**。
- §3.6.1.3 S124（P62）：任意两块装甲板下边缘高度差 ≤ **100 mm**（跨越地形时允许短暂超差）。
- §3.6.1.3 S125（P62）：装甲板下边缘离地高度 ≤ **400 mm**。
- 表 3-3（P45）：步兵/重装/哨兵均装 **4 个小装甲模块**。

装甲模块外形/灯条尺寸是官方硬件规格；`solver.cpp` 目前按小装甲 135 mm、大装甲 230 mm、灯条 56 mm 使用，这部分可以作为已知先验。

因此正确的建模方向是：**4 块板、90° 分布、板面 15° 俯仰、各板中心偏移/高度差有规范上界**，但每块板的 `r_i/z_i` 和整体倾角必须由观测在线估计；不能用仿真的具体半径代替。

### 已排除

- 不是云台姿态/相机外参问题：本轮修正后，静止/平地目标相对实时 GT 的误差已在 0.05 m / 2° 内，重投影 < 20 px。
- 不是简单的初始化参数问题：试过把英雄初始半径改为 0.24 m、收紧 `r/l/h` 的 `P0`，结果更差（`w` 冲到 −12 rad/s，重投影 44 px），已回退。

### 已实现（P1，2026-11-15）

状态从 11 维扩到 13 维，`x[11]/x[12]` 为装甲环 roll/pitch。`h_armor_xyz()` 先在环平面内放半径和高度差，再乘 `Rx(roll) * Ry(pitch)`；零倾角时退回原来的水平环。观测扩成 6 维 `[yaw, pitch, distance, armor_yaw, armor_pitch, armor_roll]`，雅可比对同一 `h()` 做中心差分。1 号英雄仍是四块大装甲，初始半径 0.25 m，没有硬编码四块板各自的半径。

NIS 阈值按观测维度取：4 维保持原来的 0.711，6 维用 χ²(6) 的 95% 上分位 12.592。继续用 0.711 会把正常更新判成失败。

### 已排除的修法（会破坏平地步兵）

- 锁住当前板：当前板预测位置还在 0.35 m 内就不再换板。平地步兵换板时旧板预测仍在附近，新板观测被写进旧板，整车被拉到十几米外。已回退。
- 把板面 yaw 从更新里拿掉、只靠位置推旋转：平地步兵的相位不再连续。已回退，板面 yaw 继续更新。

### 2026-11-17：yaw 双解改在进 EKF 之前消掉

`Solver::resolve_yaw()` 用当前装甲环 roll/pitch 重投影，在离全局最小 40 px 以内的局部极小里取离预测 yaw 最近的一个，再交给原来的朝向匹配。状态仍是 13 维，观测仍是 6 维，雅可比仍是对同一个 `h()` 的中心差分。板面 yaw 继续更新，没有锁板，也没有改成单板更新。

仿真复测（`sim_standard` 日志，未读 GT 做补偿）：

- 斜面 1 号英雄，静止：`control=true`，`w≈0`，`r≈0.266`，`id` 保持 0，不再 `diverged()`。
- 斜面 1 号英雄，匀速转：锁定后连续两分多钟 `control=true`，`w` 在 −7.0～−8.1 rad/s，`r` 停在 0.273 m。切入旋转的瞬间仍会失锁一次。每秒采样的 `last_id` 约每四次换板漏一块（`3,3,0,1,2,3`），另外三块按这个相位加 90° 推出，整圈错开。
- 平地四块小装甲步兵：静止 `w≈0`、`r≈0.20`；匀速转 `w` 在 7.0～7.8 rad/s，`r=0.207`。`last_id` 按 `0,3,2,1` 连续变化，距离保持在 1.25 m 附近，没有被拉飞。

### 2026-11-17 晚：两个半径符合规范，不扩成四块各自半径

用户确认一台机器人两个半径够用。制作规范也支持这个模型，不支持 P3 的四块各自半径：

- S120：四块板方向向量对应机体 ±X、±Y，相邻 90°。
- S121：X 轴两块板几何中心连线与 Y 轴两块板连线互相垂直；单块板相对几何中心的横向偏移 ≤ 50 mm。
- S124：任意两块下边缘高度差 ≤ 100 mm。

对角两块共用一个半径，两组差 `l`，高度差 `h`。50 mm 和 100 mm 都落在 `l`、`h` 能表示的范围内。前哨站是三块板，不在这条里面，仍见 KI-002。

### KI-002 前哨站三块装甲板被当成同一高度

- 记录日期：2026-11-17
- 状态：**已解决**（2026-11-25）：保持 13 维状态不变，在 `armor_num_ == 3` 时复用闲置 `x[9]`/`x[10]` 在线估计板 1/板 2 相对板 0 的高度差，同步更新 `Target::diverged()`、`Q` 与 `Tracker` 前哨站 `P0_dig`；`uvl_tracker_test` 新增 `OutpostThreeHeights` 回归通过（`tracked=180/180`、`med|w_err|=0.000 rad/s`、`med|h_err|=0.0001 m`、`med_px_err=0.53 px`）
- 影响模块：`tasks/auto_aim/target.cpp`、`tasks/auto_aim/tracker.cpp`、`tests/uvl_tracker_test.cpp`

`h_armor_xyz()` 在 `armor_num_ == 3` 时三块板都返回 `x[4]`。`x[9]`（半径差）和 `x[10]`（高度差）只在两块板、四块板的 `armor_offset()` 里使用；前哨站初始化又把这两维和倾角的 `P0` 置 0。现有状态里的一个 `h` 不够表示三块互不相同的高度。

仿真复测：前哨站转速收敛到 −2.51 rad/s，半径停在约 0.271 m，但 `last_id` 在 `2,0,1` 与 `2,0,2,0,1` 之间跳，`cmd_pitch` 随板号在约 −25° 和 −31° 之间跳，`control` 约每三块掉一次 false。仿真 `OUTPOST.glb` 只挂了旋转节点，没有把三块板拉到同一高度。

这块和 P3 是同一类改动：要在线估计每块板自己的高度，不能把仿真里量到的值写死。本次没有改状态量。

### 可行方向（未实现，需先确认）

**P2（视 P1 结果再定）：uv 3dof 观测**

- 把观测从 `[yaw, pitch, distance, armor_yaw]` 换成 `[u, v, armor_yaw]`；状态量不变，但 `Target` 需要拿到相机内外参和当前云台位姿，`h()` 要走投影链，雅可比可先数值；

## KI-004 武科观测（`use_uvl_ekf`）实车发散与跟随振荡

- 记录日期：2026-11-21
- 状态：**已定位根因并解决**（2026-11-21 三号步兵 Orin NX 实机已开启 `use_uvl_ekf: true` + `use_focus_roi: true` 闭环验证通过；手眼自动标定仍保留为后续精度提升项）
- 影响模块：`io/gimbal/gimbal.*`、`tasks/auto_aim/target.cpp`、`tasks/auto_aim/tracker.cpp`、`tasks/auto_aim/solver.cpp`、`src/standard_mpc.cpp`、`configs/standard3.yaml`

### 现象与证据

- 初期在三号步兵 Orin NX 实机开启 `use_uvl_ekf: true` 时频繁触发 `Target diverged!`（`r` 被拉成负值或 `l` 发散），且观测到的敌方旋转轴与实际垂直、开启云台跟随后剧烈晃动并破坏观测。

### 根因与修复

1. **下位机 IMU 坐标系与零漂/脱节（最核心原因）**：
   - 串口实测下位机四元数 `q` 存在 `+90°` 滚转安装角（`Y_imu = Z_gimbal, Z_imu = -Y_gimbal`），导致视觉世界系整体侧翻 90°；同时 IMU 存在 `+9.4°/s` 零漂，重启后 `q` 与编码器 `yaw` 偏差达 `126°`。
   - 修复：在 `io/gimbal` 新增 `R_gimbal2imu` 与 `use_euler_q`（当前下位机 IMU 不可信、电控 `yaw/pitch` 为编码器值时，由串口 `yaw/pitch` 直接构造四元数并对齐参考系）。
2. **UVL 初始化与噪声参数**：
   - 修复首帧 `Target` 倾角初值置 0（避免单帧 IPPE 镜像翻转破坏 UVL 重投影）；`Solver::armor_lightbar_depth_diff` 复用带 15° 先验的 `solve()` 消歧；灯条长度/角度观测噪声对齐 `awakening` 实车配置（`0.45 * len_px`、`sa = 0.45`）。
3. **云台跟随时与 EKF 平动速度耦合**：
   - 原 `P0[vx/vy]=64`、`v1=40` 会把云台加减速期间的微小图像-姿态错位吸成 `±4.0 m/s` 假平动速度，再叠加传递函数 MPC 预超调放大成剧烈甩头与运动模糊丢检。
   - 修复：收紧 `P0[vx/vy/vz]=4`、`P0[w]=25`、`v1=8`、`v2=40`；配置 `camera_latency_ms: 8.0`、`zero_vel_ff: true`、`gimbal_yaw_wn / gimbal_pitch_wn: 0.0`（平滑轨迹 MPC）与 `high_speed_delay_time / low_speed_delay_time: 0.060 s`（实测零相位滞后点），并修正 `standard_mpc` WebViewer 的 `ref_yaw/ref_pitch` 绑定。

### 视觉端与电控端遗留诊断（待下次上电续测）

1. **视觉端待优化项**（5 s / 369 帧专项诊断，`zero_vel_ff: false`、`gimbal_*_wn: 0.0`、`use_focus_roi: true`）：
   - **短时丢检 `NO_DET = 13.8%`**（51/369 帧，39 段 1~4 帧短脉冲）：排查方向为 `use_focus_roi` 裁剪后 `ArmorSmoother` 仍在 crop 局部坐标系内按 IoU 匹配、`min_confidence: 0.65` 偏高、以及 `use_traditional: true` 精修角点/滤除；原定 `min_confidence: 0.50` + `use_traditional: false` 对比测试因小电脑关机尚未采集，下次上电续测。
   - **灯条长度系统性偏短 ~10%**：实测 `det/pred` 长度比 `mean=0.896 / med=0.907`，需确认是 `use_traditional` 二值化收缩还是实际灯条有效发光长度偏短。

   - 当前 `configs/standard3.yaml` 保留 `use_uvl_ekf: true`、`use_focus_roi: true`、`zero_vel_ff: false`、`delay=0.020 s`、`gimbal_yaw_wn / gimbal_pitch_wn: 0.0`（已同步至 Orin NX）。

### 后续演进方案设计（2026-11-25 调研与用户确认，暂缓实现）

1. **自动外参 + 延迟联合标定（方案 1A，待 2027 新装甲板定型后实现）**：
   - **标定靶标**：不用额外标定板，直接使用静态装甲板作为标定靶（因 2027 新规则取消灯条并更换装甲板图案，待新装甲板尺寸与检测模型确定后接入；底层观测接口 `{timestamp, pts_3d, pts_2d}` 与靶标解耦）。
   - **求解原理**：两阶段纯 Eigen Levenberg-Marquardt + Huber 核直接重投影 BA（不引入 Ceres 依赖）——阶段 1 用静止/低角速度帧钉死 `R_camera2gimbal`（3 DOF）与目标世界位姿，默认固定 `t_camera2gimbal` 避免光轴平移耦合；阶段 2 用中高速摆头帧通过高频 IMU 轨迹 SLERP 插值优化 `camera_latency_ms`（1 DOF）。
   - **采集模式**：同时支持**手动扫动**（手推/遥控器）与**自动扫动**（程序发串口网格+正弦扫动），无头终端输出进度 + 可选复用 `WebViewer`，并带轴向激励覆盖度与正负号一致性自动预检。
   - **验证集成**：同步编写 `tests/extrinsic_calib_test.cpp`（合成真值验证旋转 `< 0.05°`、延迟 `< 0.2 ms`）并接入 `scripts/run_tests.sh`。
2. **明确视觉/电控分工边界**：视觉侧坚持只输出平滑可达参考轨迹 `(pos, vel, acc)`，不在视觉侧叠加云台传递函数逆模型；阻尼与动力学前馈统一下沉电控 1 kHz 闭环处理。
3. **暂不投入旧灯条模型与传统精修**：2027 赛季取消灯条、更换装甲板图案，不再针对旧灯条替换 2026 四点模型或优化传统灯条精修。
